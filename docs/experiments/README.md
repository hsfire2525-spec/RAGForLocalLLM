# 実験ログ

**設計方針（`docs/design/design.md`）とは役割が違う。**

| | 書くもの |
| --- | --- |
| `docs/design/design.md` | 何をどう作ったか、なぜその設計にしたか |
| `docs/experiments/` | 何を試して、何が起きて、次に何をするか |

設計書は最新の状態を保つよう書き換えるが、実験ログは**追記のみ**。
「あのとき何を試して駄目だったか」を後から辿れることに価値がある。

## 書き方

1ファイル = 1つの実験の流れ。`YYYY-MM-DD-<主題>.md`。

必ず入れるもの:

- **ランID** — `runs/` のディレクトリ名。数値の一次情報に辿れないログは検証できない
- **問い** — 何を確かめたかったのか
- **数値** — 信頼区間つき。点推定だけの表は「効いた」を誤読させる
- **結論と次の一手**

**うまくいかなかったこと・測定側の誤りも必ず書く。** 本リポジトリで
最も学びが大きかったのは手法の改善ではなく、**自動採点の欠陥を見つけた
経緯**だった。この種の失敗は書き残さないと同じ轍を踏む。
